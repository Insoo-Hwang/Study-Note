# 실무 노트

> **업무에서 실제로 쓰는 기술을 판 뒤, 개념과 면접 답변으로 갈라 남긴 기록.**

01~12 섹션은 "면접에서 설명할 수 있는가"를 목표로 6개 섹션 형식을 맞춰 쓴 노트다.
이 트리는 목적이 다르다. **지금 내 프로젝트에서 이 기술을 왜 이렇게 쓰고 있는지** 파고,
그것을 **면접에서 말로 뱉는 형태까지** 만들어 두는 곳이다.

그래서 노트가 항상 두 덩이다.

| 절 | 무엇이 들어가나 | 언제 읽나 |
| -- | -- | -- |
| `## 개념 설명` | 직접 판 내용 · 실제 쿼리와 로그 · 우리 코드에서 내린 결론 | 이해할 때, 다시 찾아볼 때 |
| `## 면접 질문` | 그 내용에서 뽑은 질문과 **말로 하는 답변** | 면접 전날 훑을 때 |

목적이 다르니 화면도 나눠 뒀다. 헤더의 **CS 노트 / 인프라 노트 / 실무 노트** 탭이 그 경계다.
지금은 실무 모드라 좌측 메뉴에 이 트리만 보이고 헤더도 주황색이다.
커리큘럼으로 돌아가려면 **[CS 노트](../index.md)** 탭을 누른다.

| 구분 | 01~12 커리큘럼 | 인프라 노트 | 실무 노트 |
| -- | -- | -- | -- |
| **목적** | 면접에서 설명하기 | 직접 돌려 보고 다시 찾아보기 | 쓰는 기술 이해 + 답변 만들기 |
| **주인공** | 개념 일반론 | 설치 · 설정 · 환경 | 코드 · API · 라이브러리 |
| **형식** | 6개 섹션 고정 | 자유 | **2단 고정 (개념 설명 / 면접 질문)** |
| **작성 명령** | `/study-section <번호>` | `/study-infra` | `/study-work` |
| **완결성** | 이 문서 하나로 이해되어야 함 | 메모·명령어 모음도 괜찮음 | 파다 만 것도 괜찮음 (절 안에 표시) |

## 노트 추가하는 법

**공부한 내용만 붙여넣으면 된다. 질문과 답변은 만들 필요가 없다.**
`/study-work`가 개념 설명을 정리한 뒤, 거기서 면접 질문을 뽑고 답변까지 써서 아래 형식으로 만든다.

```text
/study-work
3주차 학습 : JPA N+1과 페치 조인

JPA에서 findAll 하고 연관 엔티티 접근하니까 쿼리가 100개 나감.
페치 조인으로 바꿨는데 페이징이랑 같이 쓰니까 경고 뜨면서 메모리에서 페이징하더라.
@BatchSize 걸면 IN 절로 묶여서 쿼리 수는 줄어드는 듯. Spring Boot 3.3.4 씀.
```

같은 주제 노트가 이미 있으면 새로 만들지 않고, 개념은 `## 개념 설명`에 · 새 질문은
`## 면접 질문` 끝 번호에 이어 붙인다.

## 노트 형식

`##` 대섹션은 아래 셋뿐이다. 나머지는 전부 그 안에서 `###`로 나눈다.
직접 쓸 때도 같고, 어긋나면 검사기가 잡는다.

````markdown
# 3. JPA N+1과 페치 조인

> **컬렉션 페치 조인은 페이징과 같이 쓸 수 없고, 그 자리는 `@BatchSize`가 대신한다.**

`Spring Boot 3.3.4` · `Hibernate 6.5` · MySQL 8.0

## 개념 설명

### 왜 팠는가
주문 목록 API가 느려서 로그를 봤더니 목록 쿼리 하나에 상세 쿼리가 100개 더 나가고 있었다.

### N+1이 생기는 자리
지연 로딩된 연관을 실제로 건드리는 순간 초기화 쿼리가 하나씩 나간다.

```sql
select o1_0.id, o1_0.name from orders o1_0                     -- 1번
select i1_0.id from order_item i1_0 where i1_0.order_id = ?    -- N번
```

### 우리 코드에서는
목록 조회는 `@BatchSize(size = 100)`로 두고, 단건 상세만 페치 조인을 쓴다.

## 면접 질문

### Q1. JPA에서 N+1 문제가 무엇인가요?
**목록을 조회한 뒤 연관 엔티티를 건드릴 때마다 조회 쿼리가 한 번씩 더 나가는 것입니다.**

주문 100건을 조회하면 목록 쿼리 1번에 주문 항목 조회 100번이 더 나갑니다.
지연 로딩 자체가 문제는 아니고, 프록시를 건드리는 코드가 반복문 안에 있을 때 드러납니다.

### Q2. 페치 조인으로 풀 때 주의할 점은요?
**컬렉션 페치 조인은 페이징과 같이 쓸 수 없습니다.**

조인 때문에 행이 부풀어 DB가 몇 행을 잘라야 할지 알 수 없습니다. Hibernate는 경고
`HHH90003004`를 남기고 전체를 읽어 메모리에서 자르기 때문에 데이터가 커지면 그대로 터집니다.

## 참고
- 공식 문서 · 소스 코드 링크 (가능하면 버전이 박힌 URL로)
````

### `## 개념 설명`

붙여넣은 글을 그대로 살리되 `###` 절로 나누고, 아래 셋을 반드시 채운다.
이 셋이 없으면 반년 뒤에 못 믿는 문서가 된다.

| 빠지면 생기는 일 | 채울 것 |
| -- | -- |
| 이 동작이 지금도 맞나? | **버전** — 제목 아래에 `Spring Boot 3.3.4` · `Hibernate 6.5` |
| 이걸 왜 팠더라? | **계기** — `### 왜 팠는가` |
| 그래서 어떻게 하라는 거지? | **결론** — `### 우리 코드에서는` |

**확인 못 한 내용은 노트에 남기지 않는다.** 직접 돌려서 확인이 안 되면 공식 문서·릴리스 노트를
찾아보고, 찾았으면 근거를 문장에 박고 `## 참고`에 링크를 남긴다. 그래도 안 나오면 그 문장을 지운다.
`(미검증)` 딱지는 쓰지 않는다 — 반쯤 믿는 문장은 결국 그냥 믿게 되기 때문이다.
검색해도 답이 없는 열린 질문만 `### 아직 못 본 것` 절에 남긴다.

### `## 면접 질문`

- 질문은 `### Q1. <질문 문장?>` 꼴, **1부터 순서대로.**
- 각 질문 아래 **첫 줄은 굵은 글씨 한 줄 답.** 훑을 때 이 줄만 읽는다.
- 그 아래 설명은 **말하는 순서**로 2~4문장. 결론 → 근거 → 예시.
- 개념 설명을 문장째 복사하지 않는다. 답에 새 사실이 나오면 개념 설명에 먼저 넣는다.
- 보통 3~6개. 억지로 채우지 않는다.

## 제목과 경로

붙여넣는 첫 줄이 `3주차 학습 : …` 꼴이면 **껍데기는 떼고 주차 번호만 `N.` 으로 살린다.**

| 들어온 첫 줄 | 노트 제목 | 폴더 · 파일명 |
| -- | -- | -- |
| `3주차 학습 : JPA N+1과 페치 조인` | `# 3. JPA N+1과 페치 조인` | `03-JPA-N+1과-페치조인` |
| `12주차 학습 - Kafka 컨슈머 설정` | `# 12. Kafka 컨슈머 설정` | `12-Kafka-컨슈머-설정` |
| 주차 표기가 없는 글 | `# JPA N+1과 페치 조인` | `JPA-N+1과-페치조인` |

제목 번호는 `3.` 처럼 자릿수를 채우지 않고, 폴더명은 정렬을 위해 `03-` 으로 채운다.

```text
docs/work/<노트명>/<노트명>.md
docs/work/<노트명>/<도식>.svg
```

카테고리(데이터 접근 · 메시징 …)로 **폴더를 더 파지 않는다.** 이 트리는 주차 순서가 곧 목차다.
폴더를 한 단계 더 파면 검사기(`docs/*/*/*.md`)와 도식 경로 규칙에서 벗어난다.

- **SVG는 XML로 파싱될 것.** 외부 리소스 참조 금지

## 어느 트리에 쓸지 헷갈릴 때

세 트리가 같은 기술을 다룰 수 있다. 예를 들어 Redis는 `08-캐시-Redis`에도,
`infra/`에도, 여기에도 나올 수 있다. 기준은 **주인공이 무엇이냐**다.

| 이런 내용 | 갈 곳 |
| -- | -- |
| "Redis 자료구조와 각각의 시간 복잡도" — 어디서든 통하는 일반론 | **CS 노트** (`08-캐시-Redis`) |
| "Redis 컨테이너 올리고 AOF 설정하다 막힌 것" — 설치·설정이 주인공 | **인프라 노트** |
| "우리 서비스가 Redisson으로 분산 락 거는 방식과 그 안에서 실제 벌어지는 일" | **실무 노트** |

- **설치·설정·환경이 주인공이면 인프라, 코드와 API가 주인공이면 실무다.**
- 커리큘럼 노트와 주제가 겹치면 지우지 말고 **서로 링크한다.**
  일반론은 커리큘럼 노트에 두고, 여기서는 `../../08-캐시-Redis/...`로 걸어 둔 뒤
  "우리는 이래서 이렇게 쓴다"에 집중한다.
- 그래도 애매하면 **아무 데나 먼저 쓰고 나중에 옮긴다.** 옮기는 비용은 폴더 이동과
  등록 두 줄 수정뿐이라, 어디 쓸지 고민하다 안 쓰는 것보다 훨씬 싸다.

## 공개 저장소다 — 사내 코드를 그대로 옮기지 않는다

이 저장소는 **GitHub Pages로 공개 배포된다.** 실무 노트는 세 트리 중 이 위험이 가장 크다.
회사 코드·스키마·설정을 그대로 붙이면 그대로 인터넷에 올라간다.

**원칙: 사내 코드를 옮기지 말고, 같은 현상을 재현하는 최소 예제로 바꿔 쓴다.**
`OrderSettlementBatchService`가 아니라 `OrderService`로, 사내 도메인이 아니라 주문·상품 같은
일반적인 예로 바꾸면 노트의 가치는 그대로면서 회사 것은 남지 않는다.

| 지울 것 | 바꿔 쓸 것 |
| -- | -- |
| 사내 클래스·패키지·테이블·컬럼 이름 | 일반적인 도메인 이름 (`com.example.order`) |
| 사내 API 엔드포인트·호스트명 | `https://api.example.com` |
| 토큰 · API 키 · 비밀번호 · `.env` 값 | `<TOKEN>` · `${DB_PASSWORD}` |
| 실제 데이터 · 고객 정보가 든 로그 | 형태만 남긴 더미 값 |
| 사내 위키 · 지라 링크 | 지우거나 공개 문서 링크로 대체 |

**한 번 푸시하면 지워도 히스토리에 남는다.** 커밋 전이 유일한 기회다.
