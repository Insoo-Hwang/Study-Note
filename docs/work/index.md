이 트리는 목적이 다르다. **지금 내 프로젝트에서 이 기술을 왜 이렇게 쓰고 있는지**,

목적이 다르니 화면도 나눠 뒀다. 헤더의 **CS 노트 / 인프라 노트 / 실무 노트** 탭이 그 경계다.
지금은 실무 모드라 좌측 메뉴에 이 트리만 보이고 헤더도 주황색이다.
커리큘럼으로 돌아가려면 **[CS 노트](../index.md)** 탭을 누른다.

| 구분 | 01~12 커리큘럼 | 인프라 노트 | 실무 노트 |

## 어느 트리에 쓸지 헷갈릴 때

세 트리가 같은 기술을 다룰 수 있다. 예를 들어 Redis는 `08-캐시-Redis`에도,
`infra/`에도, 여기에도 나올 수 있다. 기준은 **주인공이 무엇이냐**다.

| 이런 내용 | 갈 곳 |
| -- | -- |
| "Redis 자료구조와 각각의 시간 복잡도" — 어디서든 통하는 일반론 | **CS 노트** (`08-캐시-Redis`) |
| "Redis 컨테이너 올리고 AOF 설정하다 막힌 것" — 설치·설정이 주인공 | **인프라 노트** |
| "우리 서비스가 Redisson으로 분산 락 거는 방식과 그 안에서 실제 벌어지는 일" | **실무 노트** |

- **설치·설정·환경이 주인공이면 인프라, 코드와 API가 주인공이면 실무다.**
- 커리큘럼 노트와 주제가 겹치면 지우지 말고 **서로 링크한다.**
  일반론은 커리큘럼 노트에 두고, 여기서는 `../../08-캐시-Redis/...`로 걸어 둔 뒤
  "우리는 이래서 이렇게 쓴다"에 집중한다.
- 그래도 애매하면 **아무 데나 먼저 쓰고 나중에 옮긴다.** 옮기는 비용은 폴더 이동과
  등록 두 줄 수정뿐이라, 어디 쓸지 고민하다 안 쓰는 것보다 훨씬 싸다.

## 노트 추가하는 법

정리한 내용을 `/study-work` 뒤에 그대로 붙여넣으면 아래 규칙에 맞춰 노트로 만들고 등록까지 한다.
같은 주제 노트가 이미 있으면 새로 만들지 않고 그 노트에 합친다.

```text
/study-work
JPA에서 findAll 하고 연관 엔티티 접근하니까 쿼리가 100개 나감.
페치 조인으로 바꿨는데 페이징이랑 같이 쓰니까 경고 뜨면서 메모리에서 페이징하더라...
```

아래는 그 명령이 지키는 규칙이고, 직접 쓸 때도 같다.

### 1. 경로

커리큘럼과 **물리 구조만 같다.** 노트마다 폴더를 하나 만들고, 파일명은 폴더명과 같게 한다.
도식(`.svg`)은 노트와 같은 폴더에 둔다.

```text
docs/work/<노트명>/<노트명>.md
docs/work/<노트명>/<도식>.svg
```

카테고리(데이터 접근 · 메시징 · 프레임워크 …)는 **폴더를 더 파지 않고** `mkdocs.yml`의 `nav`에서
묶는다. 폴더를 한 단계 더 파면 검사기(`docs/*/*/*.md`)와 도식 경로 규칙에서 벗어난다.

### 2. 노트 맨 위에 반드시 적는 것

실무 노트가 반년 뒤에 못 믿을 문서가 되는 이유는 거의 항상 **버전이 없어서**다.
`@Transactional`의 기본 전파 속성도, Kafka의 기본 `max.poll.records`도 버전에 따라 달라진다.

```markdown
`Spring Boot 3.3.4` · `Hibernate 6.5` · MySQL 8.0
```

### 3. 지켜야 하는 것 (검사기가 잡는 것)

자유 형식이지만 아래 네 가지는 커리큘럼 노트와 똑같이 검사한다.

- **파일명 == 폴더명**
- **번호 목록 아래 하위 불릿은 4칸 들여쓰기** — 3칸이면 mkdocs에서 목록이 끊긴다
- **참조한 이미지가 같은 폴더에 실제로 있을 것.** 외부 이미지(`https://…`) 금지
- **SVG는 XML로 파싱될 것.** 외부 리소스 참조 금지

```bash
python scripts/check_notes.py work
```

### 4. 공개 저장소다 — 사내 코드를 그대로 옮기지 않는다

이 저장소는 **GitHub Pages로 공개 배포된다.** 실무 노트는 세 트리 중 이 위험이 가장 크다.
회사 코드·스키마·설정을 그대로 붙이면 그대로 인터넷에 올라간다.

**원칙: 사내 코드를 옮기지 말고, 같은 현상을 재현하는 최소 예제로 바꿔 쓴다.**
`OrderSettlementBatchService`가 아니라 `OrderService`로, 사내 도메인이 아니라 주문·상품 같은
일반적인 예로 바꾸면 노트의 가치는 그대로면서 회사 것은 남지 않는다.

| 지울 것 | 바꿔 쓸 것 |
| -- | -- |
| 사내 클래스·패키지·테이블·컬럼 이름 | 일반적인 도메인 이름 (`com.example.order`) |
| 사내 API 엔드포인트·호스트명 | `https://api.example.com` |
| 토큰 · API 키 · 비밀번호 · `.env` 값 | `<TOKEN>` · `${DB_PASSWORD}` |
| 실제 데이터 · 고객 정보가 든 로그 | 형태만 남긴 더미 값 |
| 사내 위키 · 지라 링크 | 지우거나 공개 문서 링크로 대체 |

**한 번 푸시하면 지워도 히스토리에 남는다.** 커밋 전이 유일한 기회다.
