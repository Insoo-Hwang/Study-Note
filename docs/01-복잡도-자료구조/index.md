# 01. 복잡도 · 자료구조 — 한 페이지 요약

> **비용을 재는 자를 먼저 갖고, 구조가 무엇을 보장하는지 안 다음, 네 가지 질문으로 고른다.**

이 섹션 노트 6개의 핵심만 한 페이지로 모았다. 처음에는 지도로, 복습할 때는 체크리스트로 쓴다.
각 항목의 제목이 해당 노트 링크다. **자세한 근거와 실측값은 노트에 있다.**

## ① 비용을 재는 자

### [시간 복잡도와 공간 복잡도](시간-공간-복잡도/시간-공간-복잡도.md)

Big-O는 실행 시간을 재는 도구가 아니라 **입력 크기에 따른 비용의 증가율**을 표현한 것이다.

* 대표 5단계는 `O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)`이다.
* 시간은 **연산 횟수**, 공간은 **추가 메모리**를 본다. 둘은 항상 함께 판단한다.
* 같은 알고리즘도 입력에 따라 **최선 · 평균 · 최악**이 다르다. 어느 기준으로 말하는지 밝혀야 한다.
* 실행 시간을 줄이려고 메모리를 더 쓰는 **시간-공간 트레이드오프**가 성능 개선의 판단 지점이다.
* `O(1)`이 곧 빠름은 아니다. 외부 API 호출 한 번도 `O(1)`이고, 500MB 고정 버퍼도 이론상 공간 `O(1)`이다.

### [Amortized Analysis](Amortized-Analysis/Amortized-Analysis.md)

대부분 저렴하고 **가끔만 비싼** 연산은 단일 최악 비용으로 판단하면 과대평가된다.

* `ArrayList`의 마지막 삽입은 확장 시 `O(n)`이지만, 연속 삽입 기준으로는 **상각 `O(1)`** 이다.
* 용량을 일정 **배율**로 늘리기 때문에 복사 비용이 이후 삽입들에 분산된다.
* 입력 확률 분포를 가정하는 **평균 분석과 다르다.** 상각은 모든 시퀀스에서 보장된다.
* 상각 `O(1)`은 **모든 개별 연산이 항상 빠르다는 뜻이 아니다.** 확장이 일어나는 그 한 번은 여전히 `O(n)`이다.
* `ArrayList`의 **중간 · 앞 삽입은 상각 `O(1)`이 아니다.** 원소 이동 때문에 `O(n)`이다.

## ② 구조가 보장하는 것

### [선형 자료구조 비교](선형-자료구조-비교/선형-자료구조-비교.md)

선형 자료구조는 결국 **연속된 배열**이거나 **흩어진 노드를 연결한 것** 둘 중 하나다.

* 배열 계열은 **인덱스 조회가 `O(1)`**, 중간 삽입·삭제는 밀기 때문에 `O(n)`이다.
* 노드 계열은 **양 끝 조작이 `O(1)`**, 인덱스 접근은 처음부터 따라가야 해서 `O(n)`이다.
* Stack · Queue · Deque는 저장 구조가 아니라 **접근 규칙(LIFO · FIFO · 양방향)** 을 정한 추상 자료형이다.
* Java에서 Stack과 Queue 모두 **`ArrayDeque`** 가 표준에 가깝다. `Stack`과 `LinkedList`는 권장되지 않는다.
* 복잡도가 같아도 **캐시 지역성과 객체 오버헤드** 때문에 실제 성능은 크게 벌어진다.

### [해시와 트리 비교](해시-트리-비교/해시-트리-비교.md)

**"키로 정확히 찾기만 하면 되는가, 순서와 범위가 필요한가"** 로 갈린다.

* **Hash 계열** — 위치를 **계산**하므로 단건 조회가 평균 `O(1)`, 대신 순서가 없다.
* **Tree 계열** — 항상 정렬 상태를 유지해 `O(log n)`이지만, 범위 검색과 정렬 순회가 압도적으로 빠르다.
* **`LinkedHashMap`** — 해시 속도를 그대로 두고 **삽입(또는 접근) 순서**만 별도의 연결 리스트로 기억한다.
* `Set`은 별도의 자료구조가 아니라 **값을 키 자리에 넣은 Map**이다.
* Hash의 정확성은 전적으로 **`equals`와 `hashCode` 계약**에 달려 있다. 키는 반드시 불변이어야 한다.

### [Heap과 PriorityQueue](Heap-PriorityQueue/Heap-PriorityQueue.md)

전체 순서가 아니라 **"가장 급한 하나"** 만 반복해서 필요할 때 쓴다.

* Heap은 **부분 정렬**이다. 부모-자식 순서만 지키고 형제끼리는 순서가 없다.
* 그 대가로 **최댓값·최솟값 조회 `O(1)`, 삽입·삭제 `O(log n)`** 을 최악까지 보장한다.
* 완전 이진 트리라 **포인터 없이 배열 하나**로 구현된다. 가볍고 캐시 효율이 좋다.
* **Top-K에서 힙 크기를 K로 고정**하면 전체 정렬 `O(n log n)`이 `O(n log K)`가 된다. 이것이 실무 가치다.
* Java `PriorityQueue`는 **최소 힙이 기본**이고, **순회 순서는 정렬 순서가 아니다.**

## ③ 무엇을 고를 것인가

### [Collection 선택 기준](Collection-선택-기준/Collection-선택-기준.md)

선택은 두 단계다. **먼저 인터페이스, 그다음 구현체.** 순서를 바꾸면 판단이 꼬인다.

```text
1단계 — 인터페이스 : 중복을 허용하는가, 어떻게 접근하는가
    중복 O · 순서 있음 ......... List
    중복 X ..................... Set
    키로 찾는다 ................ Map
    양 끝에서 넣고 뺀다 ........ Queue / Deque

2단계 — 구현체 : 순서를 어떻게 요구하는가
    상관없다 ................... HashMap / HashSet
    넣은 순서 .................. LinkedHashMap / LinkedHashSet
    정렬 순서 .................. TreeMap / TreeSet
    우선순위 ................... PriorityQueue
```

* 잘 모르겠으면 **`ArrayList` · `HashSet` · `HashMap` · `ArrayDeque`** 네 개가 기본값이다.
* 잘못 고르면 대가가 크다. 실측에서 `ArrayList.contains`는 `HashSet` 대비 **2,000배 이상**, `LinkedList`의 인덱스 반복문은 **1,000배 이상** 느렸다.
* **`null` 허용 여부는 구현체마다 다르다.** `HashMap`은 되고 `TreeMap` · `ConcurrentHashMap` · `ArrayDeque`는 `NullPointerException`이다.
* **순서가 필요하면 반드시 명시적으로 선택한다.** `HashSet`이 정렬되어 보이는 것은 우연이고, `Set.of()`는 실행할 때마다 순서가 달라진다.

## 복잡도 치트시트

| 자료구조 | 조회 | 삽입 | 삭제 | 순서 | 기억할 것 |
| --- | --- | --- | --- | --- | --- |
| `ArrayList` | 인덱스 `O(1)` | 끝 상각 `O(1)` · 중간 `O(n)` | 끝 `O(1)` · 중간 `O(n)` | 삽입 순서 | 내부 배열 `0 → 10`에서 1.5배씩 |
| `LinkedList` | 인덱스 `O(n)` | 양 끝 `O(1)` | 양 끝 `O(1)` | 삽입 순서 | 노드 오버헤드가 커 실무에선 거의 안 쓴다 |
| `ArrayDeque` | 양 끝 `O(1)` | 양 끝 상각 `O(1)` | 양 끝 상각 `O(1)` | 삽입 순서 | Stack · Queue의 기본값 · `null` 금지 |
| `HashMap` · `HashSet` | 평균 `O(1)` | 평균 `O(1)` | 평균 `O(1)` | **없음** | table 16 · 임계값 12에서 시작 |
| `LinkedHashMap` | 평균 `O(1)` | 평균 `O(1)` | 평균 `O(1)` | 삽입(접근) 순서 | 해시 속도 + 순서 · LRU 캐시에 쓴다 |
| `TreeMap` · `TreeSet` | `O(log n)` | `O(log n)` | `O(log n)` | 정렬 순서 | 범위 검색에 강하다 · `null` 키 금지 |
| `PriorityQueue` | `peek` `O(1)` · 검색 `O(n)` | `O(log n)` | `poll` `O(log n)` | **부분 정렬** | 최소 힙 기본 · 순회 순서 ≠ 정렬 순서 |

!!! warning "표를 그대로 믿으면 안 되는 지점"

    - `HashMap`의 `O(1)`은 **평균**이다. 충돌이 심하면 Java 8부터는 트리화되어 `O(log n)`, Java 7은 `O(n)`까지 떨어졌다.
    - `PriorityQueue`의 `remove(Object)`와 `contains`는 **`O(n)`** 이다. 부분 정렬이라 이진 탐색이 안 된다.
    - 복잡도가 같아도 실제 속도는 다르다. 캐시 지역성 · 객체 오버헤드 · 오토박싱이 배수 차이를 만든다.

## 자주 틀리는 것

| 잘못된 이해 | 올바른 이해 |
| --- | --- |
| `O(1)`이면 무조건 빠르다 | 입력이 커져도 **비용이 늘지 않는다**는 뜻이다. 외부 API 호출 한 번도 `O(1)`이다. |
| 반복문이 있으면 `O(n)`이다 | 반복 횟수가 입력 크기와 무관하게 고정이면 `O(1)`이다. |
| `ArrayList.add()`는 항상 `O(1)`이다 | **마지막** 삽입이 상각 `O(1)`이다. 확장이 일어나는 그 한 번은 `O(n)`, 중간 삽입은 항상 `O(n)`이다. |
| 상각 `O(1)`과 평균 `O(1)`은 같은 말이다 | 상각은 **입력 분포 가정 없이** 모든 시퀀스에서 보장된다. 평균은 확률 가정이 붙는다. |
| `HashMap` 조회는 항상 `O(1)`이다 | **평균**이 `O(1)`이다. `containsValue`는 값에 인덱스가 없어 `O(n)`이다. |
| 힙을 순회하면 정렬 순서로 나온다 | 배열을 그냥 읽으면 뒤죽박죽이다. 정렬 순서를 얻으려면 하나씩 `poll`해야 한다. |
| `PriorityQueue`는 큐니까 FIFO다 | `Queue` 인터페이스를 구현할 뿐 **우선순위 순서**로 나온다. FIFO가 필요하면 `ArrayDeque`다. |
| `HashSet`이 정렬되어 나오더라 | 우연이다. 순서가 필요하면 `LinkedHashSet` · `TreeSet`을 **명시적으로** 골라야 한다. |

## 면접 직전에 이것만

!!! note "세 문장으로"

    1. **복잡도는 순위표가 아니라 판단 기준이다.** 데이터 크기 · 반복 조회 횟수 · 동시 요청 수를 확인하고 어느 쪽 비용을 낼지 정한다.
    2. **구조는 결국 넷이다.** 연속(배열) · 연결(노드) · 계산(해시) · 정렬(트리), 여기에 부분 정렬(힙)이 붙는다.
    3. **선택은 기본값 4개에서 시작한다.** `ArrayList` · `HashSet` · `HashMap` · `ArrayDeque`로 두고, 안 되는 이유를 측정으로 증명한 뒤에만 바꾼다.
