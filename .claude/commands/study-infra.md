# /study-infra

정리할 내용: `$ARGUMENTS`

`/study-section`이 **면접 커리큘럼(01~12)** 을 6개 섹션 형식으로 만드는 명령이라면,
이 명령은 **커리큘럼 밖의 인프라 트리(`docs/infra/`)** 를 다룬다.

**형식을 강제하지 않는다.** 6개 섹션도, 요약표도 없다.
인프라 노트는 면접 답변용이 아니라 **직접 해 보고 다시 찾아보는 기록**이기 때문이다.

> 트리를 나눠 둔 이유와 검사 규칙은 `docs/infra/index.md`에 있다. 시작 전에 한 번 읽는다.

---

## 0단계 — 입력 해석과 대상 정하기

### 입력을 어디서 읽는가

| `$ARGUMENTS` | 처리 |
| -- | -- |
| 노트 내용 (여러 줄) | 그대로 정리 대상으로 삼는다 |
| 파일 경로 하나 | 그 파일을 읽어 정리 대상으로 삼는다 |
| 짧은 주제어 하나 (`nginx 리버스 프록시`) | 아래 **내용이 없을 때** 를 따른다 |
| 비어 있음 | 현재 IDE에서 열려 있는 `docs/infra/` 하위 `.md`를 대상으로 삼는다. 그것도 없으면 아래를 따른다 |

**내용이 없을 때** — 지어내지 않는다. 인프라 노트의 가치는 *직접 해 본 것*에 있고,
그건 사용자만 알고 있다. 무엇을 했는지(명령·설정·에러 메시지·환경)를 물어보고 멈춘다.

### 새 노트인가, 기존 노트에 합칠 것인가

`docs/infra/` 아래 폴더 목록과 `docs/infra/index.md`의 노트 목록을 먼저 읽는다.

- **같은 주제 노트가 이미 있으면 새로 만들지 않고 합친다.** `Docker-이미지와-레이어` 노트가 있는데
  레이어 캐시 이야기를 또 가져왔다면 새 노트가 아니라 그 노트의 보강이다.
- 주제가 뚜렷이 다르면 새 노트를 만든다.
- **애매하면 그때만 물어본다.** 판단이 서면 어느 쪽으로 정했는지 한 줄로 알리고 그대로 진행한다.

합치는 경우에는 **기존 문단을 지우지 않는다.** 관련 절 아래에 덧붙이거나 새 절을 만든다.
기존 내용과 충돌하면(예전에 A라고 썼는데 이번에 B가 맞다고 확인됨) 지우지 말고
`~~A~~ → B (2026-08 재확인, Docker 27.x)` 처럼 **바뀐 사실과 시점을 남긴다.**
인프라는 버전이 올라가며 답이 바뀌는 일이 잦아서, 바뀌었다는 사실 자체가 정보다.

### 경로와 이름

```text
docs/infra/<노트명>/<노트명>.md
docs/infra/<노트명>/<도식>.svg
```

- **폴더명 == 파일명.** 검사기가 잡는다.
- **공백 대신 하이픈.** 조사는 빼고 핵심어만 남겨 짧게 (`Nginx 리버스 프록시 설정하기` → `Nginx-리버스프록시`).
- **카테고리 폴더를 더 파지 않는다.** `docs/infra/docker/이미지/…` 처럼 한 단계 더 들어가면
  검사기 glob(`docs/*/*/*.md`)에서 빠져 아무 검사도 받지 않는다.
  컨테이너·네트워크·CI/CD 같은 묶음은 **`mkdocs.yml`의 nav에서** 중첩으로 만든다.

## 1단계 — 노트 작성

### 붙여넣은 글을 대하는 태도

**전체를 새로 쓰지 않는다.** 사용자가 직접 해 보고 적은 것이 원본이고, 그 어투와 문단 길이를 유지한다.
하는 일은 세 가지다.

1. **틀린 것을 고친다** (2단계에서 실제로 확인한다)
2. **빠진 맥락을 채운다** — 특히 아래 세 가지는 나중의 내가 반드시 아쉬워한다
3. **다시 찾아볼 수 있게 배열한다** — 명령어 뭉치를 절로 나누고 제목을 붙인다

### 반드시 채우는 세 가지

인프라 노트가 6개월 뒤에 쓸모없어지는 이유는 거의 항상 이 셋이 없어서다.

| 빠지면 생기는 일 | 채울 것 |
| -- | -- |
| 명령이 그대로 안 먹힌다 | **버전** — `Docker 27.3`, `nginx 1.27`, `Ubuntu 24.04`. 노트 맨 위에 적는다 |
| 내 환경에선 왜 다르지? | **환경** — macOS / Windows / WSL2 / 서버. Docker Desktop인지 엔진인지까지 |
| 이걸 왜 했더라? | **목적** — 무엇을 하려다 이걸 하게 됐는지 한 줄 |

### 뼈대 — 노트 성격에 따라 고른다 (강제 아님)

붙여넣은 글이 이미 자기 구조를 갖고 있으면 **그 구조를 존중하고 억지로 맞추지 않는다.**
막막할 때 고르는 출발점일 뿐이다.

### 지켜야 하는 것 (검사기가 잡는다)

자유 형식이지만 이 넷은 커리큘럼 노트와 똑같이 검사한다.

- **파일명 == 폴더명**
- **번호 목록 아래 하위 불릿은 4칸 들여쓰기** — 3칸이면 mkdocs에서 목록이 끊긴다
- **참조한 이미지가 같은 폴더에 실제로 있을 것.** 외부 이미지(`https://…`) 금지
- **SVG는 XML로 파싱될 것.** 외부 리소스 참조 금지

코드 블록 언어 태그(` ```bash `, ` ```nginx `, ` ```yaml `)도 붙인다 — 없으면 경고가 뜬다.
셸 세션은 ` ```bash `, 설정 파일은 그 파일의 언어를, 출력만 있으면 ` ```text `를 쓴다.

### 공개 저장소다 — 붙여넣기 전에 지운다

이 저장소는 **GitHub Pages로 공개 배포된다** (`https://Insoo-Hwang.github.io/Study-Note/`).
터미널 출력과 설정 파일을 그대로 붙이면 다음이 딸려 들어온다. **작성 전에 훑고 치환한다.**

| 지울 것 | 바꿔 쓸 것 |
| -- | -- |
| 토큰·API 키·비밀번호·`.env` 값 | `<TOKEN>` · `${DB_PASSWORD}` |
| 사내 호스트명·내부 도메인 | `internal.example.com` |
| 공인 IP·서버 IP | `203.0.113.10` (문서용 대역) |
| SSH 개인키·인증서 본문 | `-----BEGIN ... (생략) -----` |
| 실명·계정 ID가 박힌 경로 | `/home/user/...` |

**한 번 커밋해서 푸시하면 지워도 히스토리에 남는다.** 커밋 전에 잡는 것이 유일한 기회다.
지운 자리에는 `<TOKEN>`처럼 **무엇이 들어갈 자리인지** 남겨 둔다.

## 2단계 — 사실 검증 (건너뛰지 않는다)

인프라는 기억으로 쓰면 거의 틀린다. 명령 하나, 옵션 하나가 버전에 따라 바뀐다.
**노트에 적은 명령은 실제로 실행해서 출력을 확인한다.**

```bash
docker --version && docker compose version    # 먼저 버전을 확정하고 노트 맨 위에 적는다
nginx -v
kubectl version --client
```

특히 아래는 반드시 실측한다.

- **명령과 옵션이 지금 버전에서 유효한지** — `docker-compose`(하이픈)는 v1, `docker compose`는 v2다.
  없어진 플래그, 이름이 바뀐 서브커맨드를 그대로 적는 일이 가장 흔하다.
- **기본값** — 포트, 경로, 타임아웃, 재시작 정책. "기본이 3초"류는 문서에서 확인하거나 직접 조회한다.
- **설정 파일 위치** — 배포판·설치 방식(패키지 / Docker Desktop / brew)에 따라 다르다.
- **출력 형태** — 노트에 붙인 출력이 실제 출력과 다르면 나중에 다른 문제로 착각한다.

검증용 임시 컨테이너·설정은 **스크래치패드**에 만들고, 확인이 끝나면 정리한다.

> **환경을 바꾸는 명령은 먼저 확인받는다.** 조회(`ps`, `inspect`, `--version`, `config`)는 그냥 실행하되,
> 사용자 머신의 상태를 바꾸는 것(`rm`, `prune`, `down -v`, 설정 파일 덮어쓰기, 포트 점유)은
> 무엇을 왜 실행하는지 말하고 승인받는다. 학습 노트를 쓰다가 남의 개발 환경을 깨면 안 된다.

**확인할 수 없는 것은 확인할 수 없다고 노트에 적는다.** 서버가 없어서 못 돌려 본 부분에
`(미검증 — 로컬에서만 확인)`을 달아 두는 편이, 확인한 것처럼 적어 두고 나중에 믿는 것보다 낫다.

검증에서 틀린 내용을 찾으면 노트 전체에서 **빠짐없이** 고친다. 한 곳만 고치면 문서 안에서 모순이 생긴다.

## 3단계 — 도식 (필요할 때만)

인프라는 **구성도 한 장이 글 세 문단을 대신하는** 경우가 많다. 좋은 후보는 이렇다.

- 요청이 지나가는 경로 (클라이언트 → LB → 리버스 프록시 → 앱 → DB)
- 컨테이너·네트워크·볼륨의 관계
- 배포 파이프라인 단계
- 계층 구조 (이미지 레이어, 쿠버네티스 오브젝트)

만드는 규칙은 커리큘럼 노트와 **완전히 같다.** 트리가 달라도 도식 스타일은 하나로 간다.

- **`scripts/svg_kit.py`를 import해서 Python으로 생성한다.** 그림판·외부 이미지 생성 금지 —
  재현 가능하고 텍스트로 diff 되어야 한다. 주로 쓰는 것은
  `head()` · `cell()` · `band()` · `arrow()` · `line()` · `txt()` · `circle()` · `save()`다.
- 생성 스크립트는 **스크래치패드**에 두고 결과 `.svg`만 노트와 같은 폴더에 저장한다.
- **색만으로 구분하지 말고 라벨을 직접 붙인다** (색약 대응).
- **`<text>`는 연속 공백을 하나로 접는다.** 나열은 ` · `나 ` / `로 잇는다.
- **`band()`는 label을 `y+21`, sub를 `y+38`에 그린다.** 높이를 46보다 작게 주면 sub가 카드 밖으로 나간다.

만든 뒤 **반드시 눈으로 확인한다.**

```bash
python scripts/preview_svg.py "docs/infra/<노트명>/<파일>.svg"
```

생성된 `*.preview.png`를 Read 도구로 열어 라벨 겹침·잘림·어색한 배치를 본다.
본문에는 표준 마크다운으로 넣고 **바로 아래에 이탤릭 캡션 한 줄**을 붙인다.

```markdown
![무엇을 보여주는 그림인지](파일명.svg)

*그림이 말하는 결론 한 줄.*
```

## 4단계 — 등록 (두 곳뿐)

### 1. `docs/infra/index.md`의 노트 목록

```markdown
### 컨테이너

- [Docker 이미지와 레이어](Docker-이미지와-레이어/Docker-이미지와-레이어.md)
```

- 링크는 **`docs/infra/` 기준 상대 경로**다. 검사기가 이 경로로 등록 여부를 본다.
- 첫 노트를 추가할 때는 `아직 작성한 노트가 없다` 문단과 예시 주석(`<!-- 예시 … -->`)을 **지우고**
  실제 목록으로 바꾼다.
- 노트가 3~4개를 넘으면 `###` 카테고리로 묶는다.

### 2. `mkdocs.yml`의 `인프라 노트` 그룹

```yaml
  - 인프라 노트:
      - infra/index.md                   # ← 라벨 없이. 이 줄을 항상 첫 줄로 유지한다
      - Docker 이미지와 레이어: infra/Docker-이미지와-레이어/Docker-이미지와-레이어.md
```

- **`인프라 노트`는 최상위 항목 그대로 둔다.** 최상위 항목은 `CS 노트`와 `인프라 노트` 둘뿐이고
  Material의 `navigation.tabs`가 이 둘을 헤더의 탭 — 즉 모드 전환 버튼 — 으로 그린다.
  이 그룹을 `CS 노트` 안으로 넣거나 최상위 항목을 하나 더 만들면 두 모드 구분이 깨진다.
- **`infra/index.md`를 첫 줄에서 밀어내지 않는다.** 그 자리를 뺏으면 `인프라 노트` 탭이
  링크가 아니라 그냥 펼침 토글이 된다 (Material의 `navigation.indexes`).
- 카테고리가 필요해지면 이 그룹 **안에서** 중첩한다.
  ```yaml
    - 인프라 노트:
        - infra/index.md
        - 컨테이너:
            - Docker 이미지와 레이어: infra/Docker-이미지와-레이어/Docker-이미지와-레이어.md
  ```
- **01~12 커리큘럼 항목의 순서·이름은 건드리지 않는다.**

### 넣지 않는 곳

- `docs/index.md` (커리큘럼 목차)
- `README.md`의 커리큘럼 트리와 진행률 표(`작성 완료 N개 / 전체 51개`)

**두 트리를 갈라 둔 이유가 이것이다.** 인프라 노트는 51개 집계에 들어가지 않는다.
(`README.md`의 `# 인프라 노트 (커리큘럼 밖)` 절은 규칙 설명이라 노트마다 고칠 필요 없다.)

## 5단계 — 검사

```bash
python scripts/check_notes.py infra      # python이 없으면 python3
```

인프라 트리에서는 **6개 섹션·요약표를 검사하지 않는다.**
파일명·들여쓰기·이미지·SVG·등록만 본다. **오류가 0이 될 때까지 고친다.**

> `[ERROR] docs/infra/index.md 목차에 링크가 없다` 가 뜨면 4단계-1을 빠뜨린 것이고,
> `[ERROR] mkdocs.yml nav에 등록되지 않았다` 는 4단계-2를 빠뜨린 것이다.

```bash
python -m mkdocs build --strict
```

깨진 링크·이미지·nav 참조를 잡는다. 실패하면 고치고 다시 빌드한다.

도식을 추가했다면 로컬 서버로 실제 렌더링까지 본다. **확인 후 서버는 반드시 종료한다.**

```bash
python -m mkdocs serve -a 127.0.0.1:8765
# http://127.0.0.1:8765/Study-Note/infra/<노트명>/  (베이스 경로 /Study-Note/ 주의)
```

미리보기 PNG로 이미 확인했고 도식 폭이 780px 이하면 이 단계는 건너뛰어도 된다.
건너뛰었다면 그 사실을 보고한다.

## 6단계 — 커밋 확인받기

1. 확인용 PNG를 지운다.
   ```bash
   rm -f docs/infra/*/*.preview.png
   ```
2. `git status`로 변경 파일을 확인하고 `site/`·`.obsidian/`이 섞이지 않았는지 본다.
3. **`git diff`로 비밀정보가 남지 않았는지 마지막으로 훑는다** (1단계의 표). 커밋 전이 마지막 기회다.
4. 사용자에게 보고한다.
    - 새로 만든 노트인지 기존 노트에 합친 것인지, 그 판단 근거
    - **2단계에서 확인한 것과 고친 것** — 버전·명령·기본값이 실제와 달랐던 부분
    - 확인하지 못해 `(미검증)`으로 남긴 부분
    - 추가한 도식과 각각이 보여주는 것
    - 검사·빌드 통과 여부
5. **커밋/푸시 여부를 확인받는다. 확인 전에는 커밋도 푸시도 하지 않는다.**

```bash
git add docs/infra mkdocs.yml
git commit -F <메시지파일>      # 여러 줄이면 파일로 넘긴다
```
